# FACAI URL 被动体检：开源选型与接入边界

领取带证据和修复建议的完整报告。这里的风险只指**实际观察到的公开配置/暴露线索**；
URL 视角无法确认服务端所有 PHP 代码漏洞，也不代替源码审计。

## 产品接入位置

- FACAI Intent/Mission：保存原始 URL、提交人、范围、采集预算、状态与 Trace。
- URL 规范化与目标约束：只接受 http/https；同域公开页面、明确页数/深度/
  时间/并发上限；不提交表单、不修改参数、不进行登录尝试或主动漏洞验证。
  URL 重定向和 DNS 解析变化仍需重新校验，避免越出登记域及访问内网地址。
- Worker：利用现有任务租约与重试，只读采集结果按页面/响应存证；
  同一 URL/规则版本有幂等键，失败如实返回，避免重复计费或假结果。
- 风险评级：仅以真实响应、采集时间和明确规则生成发现项。
  评级须附规则版本、URL、证据摘要/哈希、影响说明与不确定性；
  版本推断不能写成“漏洞已证实”。
- Trust/Proof：复用 `facai/trust.py` 的 Evidence、Claim、Proof、Artifact/Trace；
  完整报告只给完成控制权验证的领取者，公开预览不含敏感路径详情。
- Owner/运维：并发、预算、异常率、停止/重试与审计通过现有 FACAI 控制面，
  不另造一个无记录扫描队列。批量只用于已逐个完成控制权验证的站点。

## 最快可交付顺序

1. **报告领取路径**：域名控制权验证、领取授权记录、Owner 隔离、报告访问审计。
   验收：未验证者只见安全预览，跨站点/跨Owner不能领取详情。
2. **只读采集**：先用现有 `httpx` 做少量公开页面和 HTTP 配置证据；
   页数/深度/并发/时限硬限制、重定向与地址复核。验收：站点范围不外溢、
   超时明确失败、重复任务幂等；不使用任何主动漏洞载荷。
3. **评级与报告**：借鉴现行 MDN Observatory 的可解释指标，
   与 FACAI Evidence/Proof 格式融合；低可信推断保持 UNKNOWN。
   验收：每条风险能回溯到具体观察，报告可复算且不泄漏其他用户资料。
4. **规模化**：必要时再引入 Scrapy 的成熟调度/抓取组件，按许可证保留来源。
   对已验证站点逐级负载测试与停机恢复；真实公网 URL 的测试必须有明确范围。

这份选型不代表 URL 体检 API 已实现，更不代表可以保证“检测所有 PHP 漏洞”。
