# 架构决定与兼容策略

本文件记录用户冻结决定和工程兼容选择。新增日常实现不必再次请求批准；若确实要
削弱/替换核心、删除有效能力或改变用户范围，记录影响并交Owner决定。

| 决定 | 来源/状态 | 后续实现约束 |
|---|---|---|
| ADR01 FACAI是Intelligence Operating Platform | 用户冻结 | 不降级聊天壳/单Agent/静态演示 |
| ADR02 保持真实Intent和五段边界 | 用户冻结 | 理解/确认/授权/执行/验证分离，另有Owner接受 |
| ADR03 兼容旧自动Mission grant路径 | 当前源码事实+增量策略 | 新确认不issue_grant；不能无迁移改变全部旧渠道/测试 |
| ADR04 FACAI Core为总控 | 用户冻结 | Shannon附属执行；Kali/BlackArch独立工具子系统，权限仍在FACAI |
| ADR05 Rust增量接入 | 用户指定方向+兼容策略 | 当前生产骨架Python继续运行；Rust先契约/一致性验证，不全面重写 |
| ADR06 SQLite与内置调度器优先复用 | 当前源码事实+兼容策略 | 先增量迁移；拆多服务须解决队列/租约/事件归属，不能复制五容器抢任务 |
| ADR07 Evidence完整性不等于事实验证 | 用户冻结+legacy兼容 | 保留旧/proof形状，新版本分别记录完整性/语义/接受 |

| ADR11 交付包整合同一真实仓库 | 用户当前指令 | 校对旧ZIP、保留已验证能力、加入新方向/续接文件并更新manifest |

## 当前需要工程处理的冲突

- 新版确认要求不授权；旧Store.create会自动grant。采用新增明确参数/事务路径，
  保留旧调用默认行为，先测试再接入。当前没有提交未验证的Store改动。
- 当前scheduler上限8、OpenCode默认串行，与20+Agent目标有差距。采用逐层容量/租约
  和资源隔离验证；不能直接取消串行锁宣布完成。
- 当前build_proof.verified只检查终态和成本，用户要求Evidence/Proof语义验证。
  采用新增版本字段/服务，不能不兼容地改旧verified或误标已验证。
- GitHub当前远端main HEAD已与最初本地公开快照历史变化。保留本地全部历史并推独立
  开发分支，不能覆盖新main来解决同步。当前403为外部阻塞。
- Docker内置agent CLI缺失时只能运行API/调度服务；应明确UNCONFIGURED/缺运行时，
  不能把容器health当作真实AI任务可执行。

发现新冲突时追加：现象→源文件/证据→影响的核心ID→兼容选项→选择与验证。
